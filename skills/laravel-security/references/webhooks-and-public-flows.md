# Webhooks and public multi-step forms (categories 4 and 5)

## 1. Generic HMAC webhook middleware

Verify over the **raw body** (`$request->getContent()`), never over re-encoded JSON (key order
and escaping change the bytes). Compare with `hash_equals`. Reject before any DB work.

```php
final class VerifyHmacSignature
{
    public function handle(Request $request, Closure $next, string $provider): Response
    {
        $cfg = config("webhooks.$provider");       // ['header' => ..., 'algo' => 'sha256', 'secret' => ...]
        $secret = (string) ($cfg['secret'] ?? '');
        $given = strtolower(trim((string) $request->header($cfg['header'])));

        if ($secret === '' || $given === '') {
            abort(401);                             // fail closed on missing config or header
        }

        $expected = hash_hmac($cfg['algo'], $request->getContent(), $secret);
        abort_unless(hash_equals($expected, $given), 401);

        return $next($request);
    }
}
```

Providers that sign `timestamp.body` (Stripe style) additionally need a timestamp tolerance
check against replay. Use the provider SDK when one exists.

## 2. Shoptet webhooks

Facts from the Shoptet developer docs (developers.shoptet.com/webhooks, verified 2026-09-25):

- Header `Shoptet-Webhook-Signature` contains `hash_hmac('sha1', $messageBody, $signatureKey)`
  (hex).
- `signatureKey` is generated by `POST /api/webhooks/renew-signature-key` and is stored by
  Shoptet per add-on and e-shop. Store it per e-shop on your side (encrypted cast).
- Notifications are sent only from `185.184.254.0/24`.
- Ack with HTTP 200 within **4 s**, otherwise resent after 15 min, up to 3 attempts total;
  after the last failure the webhook is marked inactive.
- Recommended processing: store the event identifier, do the work asynchronously.
- Default body = metadata only (`eshopId`, `event`, `eventCreated`, `eventInstance`); full
  payload is opt-in (`sendPayload: "full"`) and may be missing on transient errors.

```php
final class VerifyShoptetWebhookSignature
{
    public function handle(Request $request, Closure $next): Response
    {
        if (! IpUtils::checkIp((string) $request->ip(), '185.184.254.0/24')) {
            abort(403);        // defense in depth; requires correct trustProxies behind a proxy
        }

        $raw = $request->getContent();
        $eshopId = (int) (json_decode($raw, true)['eshopId'] ?? 0);
        $key = ShopConnection::where('eshop_id', $eshopId)->value('webhook_signature_key'); // 'encrypted' cast
        $given = strtolower((string) $request->header('Shoptet-Webhook-Signature'));

        if (! $key || $given === '' || ! hash_equals(hash_hmac('sha1', $raw, $key), $given)) {
            abort(401);
        }

        return $next($request);
    }
}
```

Note: the key lookup uses `eshopId` from the unverified body, which is fine: a forged
`eshopId` just selects a key the attacker does not know. Resolve the shop again from the
verified payload afterwards, never from the URL.

Controller: dedup, store, queue, answer fast.

```php
public function __invoke(Request $request): Response
{
    $p = $request->validate([
        'eshopId' => ['required', 'integer'],
        'event' => ['required', 'string', 'max:64'],
        'eventCreated' => ['required', 'string'],
        'eventInstance' => ['required', 'string', 'max:64', 'regex:/^[A-Za-z0-9\-_.:]+$/'],
    ]);

    $event = WebhookEvent::firstOrCreate(               // UNIQUE(provider, dedup_key)
        ['provider' => 'shoptet', 'dedup_key' => hash('sha256', $request->getContent())],
        ['payload' => $p, 'status' => 'pending'],
    );

    if ($event->wasRecentlyCreated) {
        ProcessShoptetEvent::dispatch($event->id)->onQueue('webhooks');
    }

    return response()->noContent(200);
}
```

`eventInstance` is interpolated into Shoptet API URLs later; the regex plus
`rawurlencode()` at the call site stops `../customers/x` style traversal into other
endpoints.

Destructive events: re-fetch, then decide.

```php
final class ProcessShoptetEvent implements ShouldQueue, ShouldBeUnique
{
    use Queueable;

    public int $tries = 5;
    public int $timeout = 60;                  // < retry_after of the connection
    public array $backoff = [10, 60, 300];

    public function __construct(public int $eventId) {}

    public function uniqueId(): string { return (string) $this->eventId; }

    public function handle(ShoptetClient $api): void
    {
        $e = WebhookEvent::findOrFail($this->eventId);
        $shop = Shop::where('eshop_id', $e->payload['eshopId'])->firstOrFail();

        if (str_ends_with($e->payload['event'], ':delete')) {
            $id = rawurlencode($e->payload['eventInstance']);
            $status = $api->for($shop)->status("/api/orders/{$id}");   // your client
            if ($status !== 404) {
                $e->update(['status' => 'ignored', 'note' => "provider says $status"]);
                return;                        // payload claimed delete, provider disagrees
            }
        }

        // ... apply change, then:
        $e->update(['status' => 'done']);
    }
}
```

Also: heavy "resync everything" handlers triggered by config webhooks must be queued and
deduplicated, otherwise a burst of events drains the provider API rate limit.

```php
{
    Queue::fake();
    ShopConnection::factory()->create(['eshop_id' => 1, 'webhook_signature_key' => 'k']);
    $body = json_encode(['eshopId' => 1, 'event' => 'order:update',
        'eventCreated' => '2026-09-25T10:00:00+0200', 'eventInstance' => '2026000123']);
    $server = $this->shoptetServer() + ['HTTP_SHOPTET_WEBHOOK_SIGNATURE' => hash_hmac('sha1', $body, 'k')];

    $this->call('POST', '/webhooks/shoptet', [], [], [], $server, $body)->assertOk();
    $this->call('POST', '/webhooks/shoptet', [], [], [], $server, $body)->assertOk();

    Queue::assertPushed(ProcessShoptetEvent::class, 1);
}

public function test_delete_event_does_not_delete_when_provider_still_has_record(): void
{
    Http::fake(['*/api/orders/*' => Http::response(['data' => []], 200)]);
    $order = Order::factory()->create(['shoptet_code' => '2026000123']);
    $event = WebhookEvent::factory()->shoptetDelete('2026000123')->create();

{
    return ['REMOTE_ADDR' => '185.184.254.10', 'CONTENT_TYPE' => 'application/json'];
```

## 3. Public multi-step forms (wizards)

Typical shape: step 1 asks for order number + email, later steps show order items, let the
customer choose items, upload photos, enter a bank account. The bug class: an identifier the
user typed ends up in the session (or a hidden field) before it was verified, and later steps
trust it.

```php
// BAD: stored before verification; later steps re-query by number
session(['wizard.order_number' => $request->order_number]);
$order = $this->findOrder($request->order_number, $request->email);
if (! $order) return back()->withErrors(...);
// step 3:
$order = Order::where('order_number', session('wizard.order_number'))->first();
```

```php
// GOOD: step 1
public function verify(Request $request): RedirectResponse
{
    $data = $request->validate([
        'order_number' => ['required', 'string', 'max:32'],
        'email' => ['required', 'email'],
    ]);

    $order = Order::where('order_number', $data['order_number'])
        ->whereRaw('LOWER(email) = ?', [mb_strtolower($data['email'])])
        ->first();

    if (! $order) {
        $request->session()->forget('wizard');
        return back()->withErrors(['order_number' => __('We could not verify these details.')]); // same text for every failure
    }

    $request->session()->regenerate();
    $request->session()->put('wizard', ['order_id' => $order->id, 'verified_at' => now()->timestamp]);

    return to_route('claims.items');
}

// every later step
private function wizardOrder(Request $request): Order
{
    $w = $request->session()->get('wizard');
    abort_unless($w && now()->timestamp - $w['verified_at'] < 3600, 403);

    return Order::findOrFail($w['order_id']);
}
```

Routes: `throttle:10,1` on `verify`, session-bound middleware on the rest. After N failures,
show a captcha.

Bounded quantities and repeated claims (lock the order's items):

```php
DB::transaction(function () use ($order, $lines) {
    $items = $order->items()->lockForUpdate()->get()->keyBy('id');
    foreach ($lines as $line) {

        abort_if($line['quantity'] < 1 || $line['quantity'] > $item->quantity - $already, 422);
    }
    // create claim + lines
});
```

State machine guard for public status links (for example "accept deduction" moving a claim
to "awaiting refund"):

```php
enum ClaimStatus: int
{
    case AwaitingCustomerDecision = 8;
    case AwaitingRefund = 9;

    public function canTransitionTo(self $to): bool
    {
        return match ($this) {
            self::AwaitingCustomerDecision => $to === self::AwaitingRefund,
            default => false,
        };
    }
}

abort_unless($claim->status->canTransitionTo(ClaimStatus::AwaitingRefund), 409);
```

Combine with a single-use signed link (authorization.md section 6) so the transition fires
once, and log who and when.

Uploaded file references coming back from the client:

```php
// upload step stores what this session uploaded
$path = $request->file('photo')->store("claims/tmp/{$request->session()->getId()}", 'local');
$request->session()->push('wizard.uploads', $path);

// submit step accepts only those
$paths = array_values(array_intersect($request->input('image_paths', []), session('wizard.uploads', [])));
```

Also cast item IDs used as session keys to int (`'item_id' => ['required', 'integer']`): a
dotted string like `a.b` writes into other session keys through `session()->put("x.$id", ...)`.
